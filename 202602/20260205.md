> ### 1️⃣ Firestore 쿼리 개념
>
> **쿼리란?** <br>
> : 쿼리(Query)는 **"어떤 데이터를 어떻게 가져올 것인가?"**를 정의하는 것
>
> - 특정 카테고리의 글만 보기
> - 내가 쓴 글만 보기
> - 특정 기간의 글만 보기
> - 검색어가 포함된 글 찾기
>
> **Firestore 쿼리 함수들**
>
> | 함수           | 역할                   | 예시                    |
> | -------------- | ---------------------- | ----------------------- |
> | `where()`      | 조건 필터링            | 카테고리가 'react'인 글 |
> | `orderBy()`    | 정렬                   | 최신순, 오래된순        |
> | `limit()`      | 개수 제한              | 10개만 가져오기         |
> | `startAfter()` | 커서 기반 페이지네이션 | 다음 페이지             |
>
> ---
>
> ### 2️⃣ where - 조건 필터링
>
> **1. 기본 where 사용법**
>
> ```bash
> import { query, where, collection, getDocs } from 'firebase/firestore';
>
> // 카테고리가 'react'인 게시글만 조회
> const q = query(
>   collection(db, 'posts'),
>   where('category', '==', 'react')
> );
> ```
>
> **2. where 연산자 종류**
>
> | 연산자           | 의미         | 예시                                               |
> | ---------------- | ------------ | -------------------------------------------------- |
> | `==`             | 같음         | `where('category', '==', 'react')`                 |
> | `!=`             | 다름         | `where('category', '!=', 'etc')`                   |
> | `<`              | 작음         | `where('views', '<', 100)`                         |
> | `<=`             | 작거나 같음  | `where('views', '<=', 100)`                        |
> | `>`              | 큼           | `where('views', '>', 100)`                         |
> | `>=`             | 크거나 같음  | `where('views', '>=', 100)`                        |
> | `in`             | 배열 중 하나 | `where('category', 'in', ['react', 'typescript'])` |
> | `array-contains` | 배열에 포함  | `where('tags', 'array-contains', 'tutorial')`      |
>
> **3. 페이지네이션 흐름 시각화**
>
> ```
> [첫 번째 요청]
> getPostsWithOptions({ limitCount: 5})
>                     │
>                     ▼
>         ┌─────────────────────────────┐
>         │  Firestore에서 11개 요청     │
>         │  (limit: 5 + 1)            │
>         └─────────────────────────────┘
>                     │
>                     ▼
>         ┌─────────────────────────────┐
>         │  6개 반환됨                 │
>         │  → hasMore = true           │
>         │  → 5개만 posts에 담음       │
>         │  → lastDoc = 5번째 문서     │
>         └─────────────────────────────┘
>
>
> [더보기 클릭 - 두 번째 요청]
> getPostsWithOptions({ limitCount: 5, lastDoc: 5번째 문서 })
>                     │
>                     ▼
>         ┌─────────────────────────────┐
>         │  5번째 문서 "다음부터"       │
>         │  6개 요청 (startAfter)     │
>         └─────────────────────────────┘
>                     │
>                     ▼
>         ┌─────────────────────────────┐
>         │  3개만 반환됨                │
>         │  → hasMore = false          │
>         │  → 더보기 버튼 숨김          │
>         └─────────────────────────────┘
> ```
>

> ### 3️⃣ 복합 쿼리와 인덱스
>
> **복합 쿼리란?**
> : 여러 조건을 동시에 사용하는 쿼리
>
> ```ts
> // 카테고리가 'react'이고, 최신순 정렬
> const q = query(
>   collection(db, "posts"),
>   where("category", "==", "react"),
>   orderBy("createdAt", "desc"),
> );
> ```
>
> **인덱스가 필요한 경우**
> : Firestore에서 복합 쿼리를 사용하면 복합 인덱스가 필요
>
> ```
> ┌─────────────────────────────────────────────────────────────┐
> │  복합 인덱스가 필요한 경우                                   │
> ├─────────────────────────────────────────────────────────────┤
> │                                                             │
> │  ✅ 단일 조건 + 정렬 (같은 필드)                             │
> │     where('category', '==', 'react')                        │
> │     orderBy('category')                                     │
> │     → 인덱스 자동 생성됨                                     │
> │                                                             │
> │  ⚠️ 단일 조건 + 정렬 (다른 필드) → 복합 인덱스 필요           │
> │     where('category', '==', 'react')                        │
> │     orderBy('createdAt', 'desc')                            │
> │                                                             │
> │  ⚠️ 여러 where 조건 → 복합 인덱스 필요                       │
> │     where('category', '==', 'react')                        │
> │     where('authorId', '==', 'user123')                      │
> │                                                             │
> └─────────────────────────────────────────────────────────────┘
> ```
>

> ### 4️⃣ 실시간 리스너 (onSnapshot)
>
> **실시간 리스너란?**
> : `getDocs()`는 **한 번만** 데이터를 가져오지만, `onSnapshot()`은 **실시간**으로 데이터 변경을 감지함.
>
> ```
> ┌─────────────────────────────────────────────────────────────┐
> │  getDocs() vs onSnapshot()                                  │
> ├─────────────────────────────────────────────────────────────┤
> │                                                             │
> │  getDocs() (일회성)                                         │
> │  ────────────────                                           │
> │  [앱] ──요청──► [Firestore] ──응답──► [앱]                   │
> │        (끝)                                                 │
> │                                                             │
> │  onSnapshot() (실시간)                                      │
> │  ──────────────────                                         │
> │  [앱] ──구독──► [Firestore]                                 │
> │        ◄──데이터──┘ (변경될 때마다 자동 전송)                 │
> │        ◄──데이터──┘                                         │
> │        ◄──데이터──┘                                         │
> │                                                             │
> └─────────────────────────────────────────────────────────────┘
> ```
>
> **1. onSnapshot 사용 예시**
>
> ```ts
> import { onSnapshot, query, orderBy, collection } from "firebase/firestore";
>
> // 실시간 구독 시작
> const q = query(collection(db, "posts"), orderBy("createdAt", "desc"));
>
> const unsubscribe = onSnapshot(q, (snapshot) => {
>   const posts = snapshot.docs.map((doc) => ({
>     id: doc.id,
>     ...doc.data(),
>   }));
>
>   console.log("게시글 업데이트:", posts);
> });
>
> // 구독 해제 (컴포넌트 언마운트 시)
> unsubscribe();
> ```
>
> **2. 언제 실시간 리스너를 사용할까?**
>
> | 사용 권장       | 사용 비권장                  |
> | --------------- | ---------------------------- |
> | 채팅 메시지     | 게시글 목록 (변경 빈도 낮음) |
> | 알림            | 정적 콘텐츠                  |
> | 공동 편집 문서  | 검색 결과                    |
> | 실시간 대시보드 | -                            |

> ### 5️⃣ TanStack Query 개념
>
> **1. 왜 TanStack Query가 필요할까요?**
>
> ```ts
> // HomePage.tsx (Day 6)
> function HomePage() {
>   const [posts, setPosts] = useState<PostSummary[]>([]);
>   const [isLoading, setIsLoading] = useState(true);
>   const [error, setError] = useState<string | null>(null);
>
>   useEffect(() => {
>     const fetchPosts = async () => {
>       try {
>         const data = await getPosts();
>         setPosts(data);
>       } catch (err) {
>         setError("에러 발생");
>       } finally {
>         setIsLoading(false);
>       }
>     };
>     fetchPosts();
>   }, []);
>
>   // ...
> }
> ```
>
> **2. 문제점들**
>
> 1. 매번 상태 3개(data, loading, error)를 직접 관리해야 함
> 2. 페이지 이동 후 돌아오면 다시 로딩
> 3. 같은 데이터를 여러 컴포넌트에서 중복 요청
> 4. 에러 처리 로직 반복
> 5. 데이터 신선도(freshness) 관리 어려움
>
> **3. TanStack Query의 해결책**
>
> ```
> ┌─────────────────────────────────────────────────────────────┐
> │  TanStack Query가 자동으로 처리해주는 것들                    │
> ├─────────────────────────────────────────────────────────────┤
> │                                                             │
> │  ✅ 로딩/에러/성공 상태 자동 관리                             │
> │  ✅ 캐싱 - 같은 데이터 중복 요청 방지                         │
> │  ✅ 백그라운드 리페칭 - 오래된 데이터 자동 갱신                │
> │  ✅ 윈도우 포커스 시 자동 리페칭                              │
> │  ✅ 실패 시 자동 재시도                                      │
> │  ✅ 페이지네이션/무한 스크롤 지원                             │
> │  ✅ 낙관적 업데이트 (먼저 UI 업데이트, 서버는 나중에)          │
> │                                                             │
> └─────────────────────────────────────────────────────────────┘
> ```
>
> **4. 핵심 개념**
>
> ```
> | 개념           | 설명                                               |
> | -------------- | -------------------------------------------------- |
> | **Query**      | 데이터 조회 (GET)                                  |
> | **Mutation**   | 데이터 변경 (POST, PUT, DELETE)                    |
> | **Query Key**  | 캐시 식별자 (예: `['posts']`, `['posts', postId]`) |
> | **Stale Time** | 데이터가 "신선"하다고 간주되는 시간                |
> | **gcTime**     | 캐시에 데이터를 유지하는 시간                      |
> ```
