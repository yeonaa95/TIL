> ### 1️⃣ Firebase란?
>
> **1. Firebase 개념**
>
> Firebase는 Google이 제공하는 **앱 개발 플랫폼** <br>
> 백엔드 서버 없이도 인증, 데이터베이스, 파일 저장, 호스팅 등 다양한 기능을 사용 <br>
> 이런 서비스를 **BaaS(Backend as a Service)** 라고 부름
>
> **2. 왜 Firebase를 사용할까요?**
>
> - 기존 방식
>
> 프론트엔드 개발 + 백엔드 서버 구축 + 데이터베이스 설정 + 서버 운영... <br>
> ➡ 시간과 비용이 많이 듦
>
> - Firebase 사용
>
> 프론트엔드 개발 + Firebase 연동 <br>
> ➡ 백엔드 걱정 없이 빠르게 개발 가능!
>
> **3. Firebase의 장점**
>
> | 장점          | 설명                          |
> | ------------- | ----------------------------- |
> | 빠른 개발     | 서버 구축 없이 바로 기능 사용 |
> | 무료 시작     | 소규모 프로젝트는 무료로 충분 |
> | 확장성        | 사용량에 따라 자동 확장       |
> | Google 인프라 | 안정적이고 빠른 서비스        |
> | 실시간 동기화 | 데이터 변경 시 즉시 반영      |
>

> ### 2️⃣ Authentication (인증)
>
> 📚 공식 문서: https://firebase.google.com/docs/auth
>
> - **"누가 우리 앱을 사용하는가?"**를 관리하는 서비스
>
> **1. 지원하는 로그인 방식**
>
> - 이메일/비밀번호
> - Google, Facebook, GitHub 등 소셜 로그인
> - 전화번호 인증
> - 익명 로그인
>
> **2. 우리 블로그에서 사용할 기능**
>
> - 이메일/비밀번호 회원가입 및 로그인 (Day 1 요구사항: AUTH-001, AUTH-002)
> - Google 소셜 로그인 (Day 1 요구사항: AUTH-003)
> - 로그인 상태 유지 (Day 1 요구사항: AUTH-005)
>
> **3. 작동 원리**
>
> ```
> [사용자]                    [Firebase Auth]              [우리 앱]
>    │                              │                         │
>    │  1. 로그인 요청               │                         │
>    │  (이메일/비밀번호)            │                         │
>    ├─────────────────────────────►│                         │
>    │                              │                         │
>    │  2. 인증 확인                 │                         │
>    │◄─────────────────────────────┤                         │
>    │     (성공 시 사용자 정보)     │                         │
>    │                              │                         │
>    │                              │  3. 사용자 정보 전달     │
>    │                              ├────────────────────────►│
>    │                              │     (uid, email 등)     │
> ```

> ### 3️⃣ Cloud Firestore (데이터베이스)
>
> 📚 공식 문서: https://firebase.google.com/docs/firestore
>
> - **"데이터를 어디에 저장하는가?"**를 담당하는 NoSQL 데이터베이스
>
> **1. 특징**
>
> - **문서(Document) 기반**: JSON과 비슷한 형태로 데이터 저장
> - **실시간 동기화**: 데이터 변경 시 연결된 모든 클라이언트에 즉시 반영
> - **오프라인 지원**: 인터넷이 끊겨도 로컬에서 작동
> - **확장성**: 자동으로 확장되어 대규모 트래픽 처리
>
> **2. 데이터 구조**
>
> ```
> Firestore 데이터베이스
> │
> └── 컬렉션 (Collection) : posts
>     │
>     ├── 문서 (Document) : abc123
>     │   ├── title: "첫 번째 글"
>     │   ├── content: "내용입니다..."
>     │   ├── authorId: "user123"
>     │   └── createdAt: 2025-01-29
>     │
>     ├── 문서 (Document) : def456
>     │   ├── title: "두 번째 글"
>     │   ├── content: "다른 내용..."
>     │   └── ...
>     │
>     └── ...
> ```
>
> **3. 우리 블로그에서 사용할 기능**
>
> - 게시글 저장 및 조회 (Day 1 요구사항: POST-001 ~ POST-005)
> - 카테고리별 필터링 (Day 1 요구사항: POST-006)

> ### 4️⃣ 프로젝트 생성 및 웹 앱 등록
>
> **1. .env 파일에 설정 정보 저장**
>
> ```js
> # Firebase 설정
> VITE_FIREBASE_API_KEY=AIzaSyC_example_1234567890abcdefg
> VITE_FIREBASE_AUTH_DOMAIN=simple-memo-app.firebaseapp.com
> VITE_FIREBASE_PROJECT_ID=simple-memo-app
> VITE_FIREBASE_STORAGE_BUCKET=simple-memo-app.appspot.com
> VITE_FIREBASE_MESSAGING_SENDER_ID=123456789012
> VITE_FIREBASE_APP_ID=1:123456789012:web:abcdef1234567890
> ```
>
> **주의**:
>
> - 실제 값으로 교체하세요!
> - 따옴표 없이 입력
> - `VITE_` 접두사 확인
>
> **2. `src/App.tsx`에서 환경 변수 테스트**
>
> ```ts
> import React, { useEffect } from "react";
>
> const App: React.FC = () => {
>   useEffect(() => {
>     console.log('Firebase Config:');
>     console.log('API Key:', import.meta.env.VITE_FIREBASE_API_KEY);
>     console.log('Project ID:', import.meta.env.VITE_FIREBASE_PROJECT_ID);
>   }, []);
>
>   return (
>     ...
>   );
> };
>
> export default App;
> ```

>
>     /* Bundler mode */
>     "moduleResolution": "bundler",
>     "allowImportingTsExtensions": true,
>     "verbatimModuleSyntax": true,
>     "moduleDetection": "force",

>     "jsx": "react-jsx",

>

>     },
>   },
> });
